# Mega Evolution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add permanent Mega forms (~48): farm type Crystals + Shards outside the run, unlock Megas in the Forge, then become Mega in a run at level 36 with a Mega Stone, gaining clearly higher stats.

**Architecture:** Mega forms live in a separate table `G.MEGA_DEX` (dex ≥ 10000) merged into `G.DEX_BY` only, so every `G.DEX` list (enemies, gacha, rift, Pokédex counts) is untouched. In-run transformation reuses `Player.evolve`/`setLook` plus a reversible flat bonus. Crystals reuse the ledger in `core/db.js`.

**Tech Stack:** Vanilla JS on global `G` (no modules), Node 24 `node:test`, PokeAPI via Node `fetch`.

**Spec:** `docs/superpowers/specs/2026-10-28-mega-design.md`

## Spec amendments found while planning (apply, then keep the spec in sync)

1. **Not in `G.DEX`.** Spec §2 says "a `G.DEX` entry". Instead: `G.MEGA_DEX` array + `G.DEX_BY[megaDex]`. Reason: `enemies.js`, `events.js`, `rift.js`, `menu.js` (Pokédex, `owned / G.DEX.length`) and `gacha.js` iterate `G.DEX` and would spawn/list Megas.
2. **Passive:** a Mega inherits its base form's passive (`G.PASSIVES[mega] = G.PASSIVES[base]` at load). Spec §2 said "via gen_passives"; that pipeline needs a hand design per dex and Mega power already comes from higher BST + the fixed Mega bonus.
3. **Co-op:** no new `mega` network event. The existing `evo` event carries a dex and `mateLook` works for any `G.DEX_BY` dex. Spec §6 and `MULTIPLAYER_PROTOCOL.md` get a note instead of a protocol change.

## Global Constraints

- Edit `dev.html`, never `index.html`, `js/app.min.js`, `js/lang/`, `version.json`. Do **not** commit/push (project owner asks first; commit messages never carry AI signatures per CLAUDE.md).
- All new Mega strings **English only** (no `lang-updates.js` rows, no es/fr/it/pt/zh); still go through `G.T` / `G.I18n.f`. Changelog `js/data/changelog.js` entry in es + en under `2026-10-28` `new`. No server/DB/cost changes.
- New JS files go inside `<!-- scripts:begin/end -->` of `dev.html` in load order; essential ones also in `NEED` in `js/main.js`. `util.js` must keep `window.G = window.G || {};`.
- Mega is the final step: no evolution beyond it, not a companion (`isBase` false), not in gacha. Base form is never lost.
- Values (estimates, tunable constants at the top of each file): Mega level 36; crystals 8 (one type) or 6+6 (two types); Shards `{normal: 400, XY: 450}`; boss drops 1 crystal of its type; big chest 1 crystal of one of the player's types; weekly mission reward crystals; Mega bonus +15% damage, +20% max HP and heal 25% of max HP on transform, +8% move speed, +10% crit chance.
- Many files are CRLF, some LF (`progress.js`, `menu.js`, `evolution.js` are LF). Edit with a Node script that detects line endings and replaces a **unique** string, then grep/test; multi-line regex fails silently.
- Tests: `node --test tests/*.cjs` (Node 24 needs the glob). Baseline 145/145 must stay green.

## Review Focus

- Owning a Mega must not inflate Pokédex totals/achievements or let it become the companion (`menu.js`, `achievements.js`, `fixPartner`).
- A save from an older client without `cry` / with unknown Mega keys loads and merges without losing crystals (ledger merge takes max per entry).
- Mega with no sprite sheet of its own still renders (alias to base sheets) and never shows the fallback grey dot.
- Transforming twice or dying mid-transform must not stack the bonus or keep a stone (`pl.evolving` guard, bonus reversible).
- Co-op: guest sees host/mates become Mega via `evo` with the sprite preloaded; no desync when the Mega dex is unknown to an older client.
